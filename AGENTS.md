# Project workflow

Keep changes within the explicitly approved milestone. Test meaningful completed work before committing or publishing; do not create empty activity commits.

Before each authorized push, inspect staged/tracked files and the full reachable Git history for secrets, credentials, private briefs, learning notes, personal data and generated media. Keep private material ignored. If sensitive content is found or uncertain, stop and report before publishing or rewriting history.

Use factual commits and keep README commands, implemented features and limits accurate. Preserve earlier reports and uncertainty: manual confirmation never establishes visual or physical correctness. Do not schedule coding or expand scope from these instructions alone.
